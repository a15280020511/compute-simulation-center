# 计算中心数据准备与复杂数值问题预案

## 原则

计算中心只做确定性检查和固定算法，不联网、不搜索、不调用外部API、不调用模型、不执行任意Python、Shell或SQL。

外部数据寻找、API目录选择、来源核验和假设组织由GPTs使用中心负责。普通网页GPT只负责维修。

## 计算前置状态

每次正式计算都生成 `compute-preflight.json`：

- `DATA_READY`：数据和元数据足够；
- `DATA_READY_WITH_ASSUMPTIONS`：假设已充分记录且不需要额外批准；
- `DATA_DEGRADED`：允许计算，但结论必须附带数据质量限制；
- `USER_APPROVAL_REQUIRED`：关键低置信度假设或专家假设尚未获用户批准；
- `DATA_INSUFFICIENT`：必需数据或数值条件不足，禁止执行计算。

## 数据来源优先级

```text
API实际观测
→ 用户直接提供
→ 可核验公开资料
→ 同来源历史数据
→ 同地区/同时段基准
→ 代理数据
→ GPTs显式假设
→ 专家待检验假设
```

后一级不能伪装成前一级。专家假设必须由GPTs重构并取得必要批准后，才能进入新的计算票据。

## 缺失数据预案

1. 判断变量是否为必需；
2. 读取API能力目录，确认是否存在可取得该变量或代理变量的连接器；
3. 请求用户提供真实记录；
4. 查找同来源历史数据；
5. 使用同地区、同时段或同业务基准；
6. 使用明确标记的代理数据；
7. 使用区间或概率分布假设；
8. 仍不足则返回 `DATA_INSUFFICIENT`。

禁止静默填零、静默删除缺失样本或用未说明的默认值替代。

## 平均数据和代表值预案

- 稳定、近似对称：算术平均数；
- 样本权重不同：加权平均数；
- 分布偏态：中位数；
- 存在明显异常值：截尾平均数；
- 时段、地域或类别差异明显：分组统计；
- 样本量少：区间、分位数或情景，不输出伪精确单点；
- 没有本地数据：相似地区基准或代理值，并降低置信度。

Preflight只推荐代表值方法，不自行改变输入数据。实际代表值由固定统计operation计算，或由GPTs在票据中明确提交。

## 假设预案

每项重要假设应记录：

- 名称和值；
- 单位；
- 来源类型；
- 依据；
- 置信度；
- 敏感性最小值和最大值；
- 分布类型；
- 失效条件；
- 批准者；
- 创建时间。

处理规则：

- 高置信度：可进入基础情景；
- 中置信度：建议敏感性分析或情景比较；
- 低置信度：必须提供区间或分布，并在关键结论前取得用户批准；
- 专家假设：未由GPTs重新提交并获批准前，不得进入计算；
- 假设比例过高：标记退化或阻断，避免伪精确结论。

## 数值问题预案

Preflight和operation验证共同检查：

- NaN和Infinity；
- 除零风险；
- 概率越界；
- 概率向量和不为1；
- 维度不一致；
- 非法负数；
- 样本量不足；
- 异常值比例；
- 单位、时间和地域范围冲突；
- 奇异或病态系统风险；
- 优化无可行解；
- 不收敛；
- 时间序列不连续；
- 马尔可夫转移条件非法；
- 蒙特卡罗随机种子和迭代上限。

## 推荐的补充计算

- 中低置信度参数：`sensitivity_analysis`；
- 有上下界或概率分布：`monte_carlo`；
- 多套政策或情景：`scenario_compare`；
- 时间序列数据：`time_series_forecast`；
- 假设需要验证：`assumption_validation`；
- 排队和服务流程：`discrete_event_simulation`；
- 状态转移：`markov_simulation`。

## 结果交付要求

GPTs读取计算结果时，同时读取：

- `compute-preflight.json`；
- `compute-result.json`；
- `compute-audit.json`；
- `compute-diagnostics.json`；
- `artifact-manifest.json`。

向专家团传递时必须同时说明：

- 数据完整度；
- 观测数据与假设数据比例；
- 关键低置信度参数；
- 敏感性结论；
- 适用范围；
- 失效条件；
- 不能解释的内容。
