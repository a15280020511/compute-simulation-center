# 顶级计算仿真中心：机构级库体系与使用流程

## 核心判断

计算仿真中心必须有假设库，但不能把未经验证的领域判断预装成“真值”。机构库只保存经过命名、版本化、证据化、批准和设定有效域的假设；任务特有假设仍随票据提交，并形成不可变快照。

## 运行需要的十三类库

1. 模型库：模型用途、版本、成熟度、失效条件和退役日期。
2. 方法库：固定算法后端、依赖、输入边界和回滚。
3. 假设库：结构、参数、边界、行为、数据、数值、因果和政策假设。
4. 分布与先验库：允许的分布、参数要求和适用条件。
5. 参数与校准库：参数定义、边界、识别性、校准数据和历史结果。
6. 约束库：硬约束、软约束和独立后检查。
7. 场景库：基准、上下界、压力、逆向压力、反事实和对抗场景类型。
8. 机制覆盖库：重要现象、机制、遗漏和替代结构。
9. 实验设计库：随机种子、重复次数、停止规则、留出、步长和多起点。
10. 数据与证据库：冻结快照、来源、时间、单位、范围和SHA-256。
11. 基准与验证库：数值真值、参数恢复、冻结真实、对抗和影子运行。
12. 可信度库：按用途和风险评估数据、验证、不确定性、鲁棒性和审查因素。
13. 反馈与结果库：预测、真实结果、漂移、校准、Artifact和生命周期事件。

## 标准使用链

```text
明确决策和用途
→ 评估模型影响与错误后果
→ 登记重要机制和遗漏
→ 解析机构假设＋任务假设
→ 检查假设依赖、冲突、有效域和证据
→ 建立分布、场景、参数和约束
→ 选择固定模型和方法后端
→ 制定实验设计和数值验证计划
→ 校准、验证、敏感性、压力和替代结构比较
→ 按可信度因素逐项验收
→ 生成结果、限制、快照哈希和Artifact
→ 未来真实结果进入反馈账本并触发复核
```

## 禁止事项

- 不把专家意见、GPT假设、代理变量或插补值当成现实观测。
- 不允许票据提供代码、分布函数、求解器、SQL或包名。
- 不使用单一加权总分掩盖某个关键可信度因素不达标。
- 不用单次随机轨迹形成正式结论。
- 不在没有真实反馈时把模型标成decision-grade。
- 不允许计算中心直连实时数据库或网络。
