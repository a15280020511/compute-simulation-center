# 系统论计算矩阵

## 结论

计算中心需要形成“计算矩阵”，但这里的矩阵不是把所有知名工具安装到同一个环境，也不是再增加一个重型总控平台。

正式方案是：

```text
问题类型
× 系统层级
× 反馈结构
× 证据成熟度
× 风险等级
× 必须通过的质量门
× 受控 operation / mode
× 独立依赖矩阵
```

`systems-computation-matrix.json` 对当前 26 项公开 operation 做一一映射，`systems_matrix.py` 负责完整性校验，并把系统路线写入每次 `compute-runtime-plan.json`。

## 系统论的实际作用

系统论不替代数学算法。它负责防止计算中心出现以下失真：

1. 把观察统计当成机制或因果；
2. 把静态优化当成动态政策效果；
3. 忽略反馈、延迟、非线性、适应和路径依赖；
4. 单独运行一个工具后直接发布“最优决策”；
5. 参数未识别、未校准、未压测却进入正式结果；
6. 真实结果返回后没有形成漂移和误差反馈。

统一生命周期为：

```text
数学表述
→ 参数估计或校准
→ 仿真或优化
→ 压测与验证
→ 真实结果反馈
```

不同 operation 只启用必要阶段，避免所有任务都走一条昂贵、脆弱的全量流水线。

## 对外部“顶级纯软件架构”报告的吸收结果

### 已吸收或现有能力已经覆盖

- 约束翻译：现有 CVXPY、OR-Tools、SciPy 固定入口；
- 参数校准与逆问题：现有 OpenTURNS、校准引擎、参数恢复基准；
- 代理模型：现有 Gaussian Process、Polynomial surrogate、主动学习；
- 微观涌现：Mesa；
- 连续动态和系统反馈：现有非线性动力学与系统动力学受管模式；
- 网络拓扑：NetworkX；
- 全局敏感性：SALib / Sobol；
- 状态估计：Kalman、EKF、UKF、EnKF、粒子滤波；
- 约束残差、漂移、真实结果匹配、Artifact、SHA 和冻结基准治理。

### 当前不直接加入

以下工具不应因为“顶级架构”标签而整体接入：

- Dagster、MLflow：与现有 GitHub Actions、Artifact、Manifest、版本冻结和质量门职责高度重叠；
- Ray、Dask：当前 GitHub Runner 和任务规模没有稳定集群，加入后会增加分布式故障面；
- JAX：当前主要瓶颈不是 GPU/JIT，且会扩大平台和二进制兼容矩阵；
- Stan、PyMC：能力价值高，但与 OpenTURNS、现有贝叶斯和校准入口存在重叠，只有冻结基准证明现有能力不足时才进入候选；
- Ceres Solver、DifferentialEquations.jl：引入 C++/Julia 双生态会显著增加构建、诊断和版本维护成本；
- SMT：当前已有代理模型能力，不应为了工具名称重复建设；
- QuantLib、Backtrader：当前固定金融算子、PyPortfolioOpt 和 vectorbt 已覆盖现有范围，新增前必须有明确缺口；
- Polars、Apache Arrow：可作为未来数据量触发的性能升级，不作为默认依赖；
- Pyomo：与 CVXPY、OR-Tools 的现有固定约束入口重叠，不作为默认层。

## 工具增加门槛

任何新工具只有同时满足以下条件才可进入：

```text
现有能力存在可复现缺口
＋冻结基准证明新工具显著改善准确度或资源效率
＋不破坏网络隔离
＋拥有独立依赖矩阵
＋固定输入 Schema 和资源上限
＋故障注入、回滚和 Artifact 证据完整
```

因此，计算矩阵的核心价值不是“工具更多”，而是让现有工具按系统结构正确组合，并在错误阶段失败关闭。
