# 计算中心方法库、规则库与存储架构

## 最终结构

```text
API中心 / 用户数据
        ↓
GPTs唯一中介：结构化、来源登记、快照、SHA-256
        ↓
离线计算中心
├── 方法注册表：允许使用哪些固定算法后端
├── 模型注册表：哪些模型可用于哪些问题
├── 规则注册表：数据、假设、约束、校准、验证和生命周期规则
├── 基准注册表：真值、参数恢复、冻结真实、对抗和影子运行
├── 冻结数据快照：JSON / CSV / Parquet，只读
├── 性能反馈账本：默认JSONL，追加写入
└── Artifact：完整结果、诊断、版本、哈希和审计证据
```

## 是否需要外部方法库

需要，但必须是仓库固定版本、按 operation 隔离安装、通过适配器调用。当前已接入 SciPy、statsmodels、Mesa、NDlib、DoWhy 和 pgmpy。Optuna、PySD、PyMC/ArviZ、PEST++、Dakota 只在明确触发条件出现后启用。

## 是否需要数据库

不需要把计算中心连接到实时业务数据库、数据仓库、向量数据库或互联网数据库。实时数据由 API 中心获取，GPTs 生成不可变快照后传入计算中心。

默认存储为版本化 JSON、冻结数据文件、JSONL 反馈账本和 GitHub Artifact。只有反馈账本超过 10000 条或查询明显变慢时，才启用本地 SQLite 元数据索引；SQLite 不成为数值真值来源，计算运行期间只读，也不允许票据提交 SQL。

## 是否需要规则库

需要。规则库不保存任意表达式或脚本，而是登记固定规则 ID、实施模块、严重级别和阻断条件。实际执行仍由预先审计的 Python 模块完成。

## 不采用

- 计算中心直连生产数据库；
- 票据携带数据库凭据或 SQL；
- 用向量数据库内容作为数值真值；
- 运行时安装用户指定方法包；
- 允许规则库执行任意 DSL、表达式或代码；
- 用合成或插补数据冒充现实观测。
